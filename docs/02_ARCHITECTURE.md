# معمارية النظام المقترحة

**القرار:** Backend مستقل على New-VPS، واجهة Windows خفيفة. تنفيذ Backend الوهمي مثبت؛ المكونات الإنتاجية وWindows قيد البناء.

## الوحدات
1. **Windows Client (C# / WinUI 3):** لوحات وCRUD والبحث والإشعارات وتأكيد الرد والحذف، ولا يحتفظ بملفات جلسات واتساب.
2. **API Server (Node.js + TypeScript):** مصادقة وصلاحيات وتحقق مدخلات وإصدار أحداث وتكليفات ومهام وتنبيهات.
3. **WhatsApp Connector:** واجهة قابلة للاستبدال provider adapter، session registry، إعادة اتصال بتراجع تدريجي، تخزين حالة الجلسة مشفرة، فصل كل رقم.
4. **Ingest Worker:** قبول الرسائل من مجموعات مصرح بها فقط، normalize، deduplicate، حفظ الأصل بأقل قدر، استخراج حقول، إصدار تكليف.
5. **Rule Engine:** قواعد صريحة حسب session + group + نوع الرسالة؛ يقترح المهمة والأولوية دون ذكاء اصطناعي ما أمكن.
6. **AI Adapter:** معالج اختياري للنصوص المبهمة، مخرجات منظمة مع confidence/provenance، ومراجعة يدوية.
7. **Task Service:** المعالجة الآمنة لحالات الحساب/التكليف ومهام متعددة لكل حساب.
8. **Reply Outbox Worker:** معاينة وإقرار ثم إرسال متحكم به، idempotency وحالات تسليم ومراجعة فشل.
9. **Notifications:** أحداث لحظية عند اتصال Windows، وسجل تنبيهات دائم يعرض عند إعادة الاتصال.
10. **PostgreSQL:** الحقيقة المركزية للحسابات والمهام والمصدر والجلسات/metadata والصلاحيات والتدقيق.
11. **Backup/Health:** نسخ مشفرة وفحص استعادة ومراقبة الخدمة والموصل وقاعدة البيانات.

## تدفق البيانات
WhatsApp Group → session-scoped Connector → persistent inbox → Validation/Rules → optional AI → Review or Account/Assignment → API/Notifications → Windows user action → Reply Outbox → Connector → Original WhatsApp Message.

## حالات الاتساق
- كتابة الحدث الوارد وفهرس منع التكرار في معاملة واحدة.
- إنشاء الحساب/التكليف atomically؛ قفل أو unique constraint للسباق.
- تغيير المهمة لا يعني إرسال رد ناجح؛ Outbox يسجل كل محاولة ويمنع إعادة الإرسال الأعمى إذا كانت النتيجة مجهولة.
- عند انقطاع العميل، تظل البيانات محفوظة على VPS؛ يعود العميل ويجلب التغييرات من cursor.
- عند انقطاع واتساب تُجمع الأخطاء دون الادعاء باستلام رسائل أثناء الانقطاع؛ قد لا يمكن استرجاع كل الرسائل الضائعة.
- تصميم عدة جلسات: جميع العمليات موثقة بـ session_id؛ لا يمكن الرد برقم مختلف بسبب قيمة افتراضية خاطئة.

## توصيات تقنية قابلة للمراجعة
Windows App SDK/WinUI 3، .NET حديث مدعوم، Backend TypeScript، PostgreSQL، migrations منظمة، وسجل outbox/inbox داخل قاعدة البيانات أولًا؛ إدخال Redis لاحقًا فقط عند ظهور حاجة مثبتة. استخدام TLS أو شبكة خاصة لتواصل Windows وNew-VPS.

## الحدود بين الوحدات
تعامل provider adapters مع DTOs محددة مسبقًا. يمنع استدعاء واجهة واتساب مباشرة من منطق المهام أو UI، ويمنع وضع مفتاح الذكاء الاصطناعي أو بيانات الدخول داخل Windows installer.
